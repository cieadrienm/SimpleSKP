# DECISIONS

Journal des choix structurants : contexte, décision, ce qu'on a écarté. D1 (lecture sans SketchUp installé), le déplacement et le rendu (D6 et D7 du design, consignés ici en D12 et D13, qui remplacent les D6 et D7 initiales) sont des décisions d'Adrien du 25 octobre 2026 ; les autres ont été prises en autonomie le même jour, à partir de sa demande (« une nouvelle app, simple, légère et élégante, pour ouvrir rapidement les fichiers SketchUp ») ; toutes sont réversibles.

## Décisions

- **D1 — Le fichier est lu par le framework du SDK C de SketchUp, embarqué dans l'app.**
  - Contexte : le format `.skp` est propriétaire et non documenté ; le réécrire est un travail de mois et casse à chaque version. 412 fichiers sur ce Mac, de 11 Ko à 215 Mo, de SketchUp 8 à 2023. **Adrien, 2026-10-25 : l'app doit fonctionner sans SketchUp installé, c'est son intérêt.**
  - Décision : `SketchUpAPI.framework` (API C 11.0), chargé par `dlopen`, livré dans `SimpleSKP.app/Contents/Frameworks` par `Scripts/bundle.sh` (aminci à l'architecture de la machine, sans en-têtes, ≈ 11 Mo, re-signé avec l'identité de l'app) : pris dans `$SKETCHUP_SDK`, sinon `Vendor/SketchUpAPI.framework` (SDK officiel téléchargé chez Trimble, ignoré par git), sinon la copie du même SDK livrée avec Unity (la plus récente). Chemins cherchés par l'app dans l'ordre : `$SIMPLESKP_SKETCHUP_SDK` (tests, développement), `Contents/Frameworks` de l'app, puis — sauf si `SIMPLESKP_BUNDLED_SDK_ONLY` est posée, preuve qu'aucun SketchUp n'est requis — chaque `/Applications/SketchUp*.app` et `~/Applications/SketchUp*.app` (le plus récent d'abord ; les dylibs sœurs `libCommon*.dylib` se préchargent par chemin absolu), puis Unity. Les prototypes sont transcrits des en-têtes lus dans la copie Unity (`Versions/A/Headers`), les en-têtes ne sont pas copiés. Framework absent (app incomplète) : vignette PNG et message « réinstallez l'app ». « Ouvrir dans SketchUp » n'apparaît que si SketchUp est installé. Le framework du SDK C de SketchUp (Trimble) est embarqué dans l'app sous la licence du SDK SketchUp ; le code de SimpleSKP est GPL v3.
  - Écarté : réécrire le format (des mois de travail, cassé à chaque version) ; exiger SketchUp installé (refusé par Adrien).
- **D2 — SceneKit pour l'affichage.** Caméra, lumière, matériaux, collisions et contrôleur d'orbite fournis par le système. Faces triangulées par `SUMeshHelper`, une géométrie par lot (matériau, calque), composants convertis une fois et instanciés par géométrie partagée. Écarté : Metal nu (des dizaines de milliers de lignes), à reconsidérer si SceneKit plafonne sur les maquettes de salle.
- **D3 — Document AppKit (`NSDocument`), comme SimpleText.** L'en-tête (version, vignette) se lit en quelques millisecondes et s'affiche avant tout ; le modèle se charge ensuite en arrière-plan. `NSDocument` donne Ouvrir récent, l'association Finder, la restauration, plusieurs fichiers. SwiftUI pour l'habillage dans des `NSHostingView`. Menu construit en code (AppKit insère lui-même « Ouvrir l'élément récent » et « Plein écran », D14 de SimpleText). Écarté : `DocumentGroup`.
- **D4 — Paquet SwiftPM, macOS 15, outils 6.0, mode Swift 5, trois cibles** : `SimpleSKPCore` (sans AppKit), `SimpleSKPViewport` (SceneKit), `SimpleSKP` (app), pour que trois agents compilent chacun la leur en parallèle. Pas de projet Xcode.
- **D5 — Mètres, Z vers le haut dans le modèle neutre.** SketchUp compte en pouces (× 0,0254), Z vertical ; SceneKit a Y vertical : une seule rotation de −90° autour de X sur le nœud racine. Dimensions de la barre d'état en mètres, une décimale.
- **D6 — Manipulation à la SketchUp sur le contrôleur de caméra de SceneKit** (remplacée par D12) (`.orbitTurntable`, horizon gardé) : glisser = orbite autour du point visé au clic (test de collision, sinon le centre du modèle) ; ⇧-glisser, clic droit ou bouton du milieu = panoramique ; molette ou pincement = zoom vers le curseur ; double-clic = recentrer ; ⇧Z = zoom étendu. Vues ⌘1…⌘7, ⌥⌘P perspective / parallèle, ⌘E arêtes, ⌘[ ⌘] scènes, ⌥⌘S barre latérale. Inertie coupée.
- **D7 — Rendu « style SketchUp » sur fond sombre** (remplacée par D13). Faces blanches par défaut, double face, arêtes sauf les adoucies, phare attaché à la caméra + ambiant, pas d'ombres, antialiasing ×4, rendu à la demande (batterie). Textures écrites par `SUTextureWriteToFile` dans un dossier temporaire supprimé à la fermeture.
- **D8 — Pas d'OSC, d'API HTTP ni de MCP** (remplacée par D15) : rien à piloter dans un visualiseur (même raisonnement que SimpleText). Pas d'export, d'édition, de sections ni de styles SketchUp.
- **D9 — Interface en français avec `L("fr", "en")`**, `Localization` de la famille, `fr.lproj` et `en.lproj` minimaux pour qu'AppKit parle français. `SimpleUpdater` repris de SimplePJ (dépôt `cieadrienm/SimpleSKP`).
- **D10 — Identifiant `net.cieadrienm.simpleskp`, version `1.2.0` dans `Scripts/bundle.sh` seulement.** Rôle `Viewer` sur `com.sketchup.skp` (déclaration importée, extension `skp`, rang `Alternate` : SketchUp reste propriétaire). Signature Developer ID avec runtime durci ; le framework embarqué est re-signé avec l'identité de SimpleSKP, la validation des bibliothèques passe donc sans l'entitlement `com.apple.security.cs.disable-library-validation` (gardé, sans effet néfaste) ; signature Apple Development sans runtime durci sinon, comme les sœurs. `bundle.sh` : architecture de l'hôte seulement, `Info.plist` gabarit estampillé (échec si non estampillé), `NOTARIZE=1` possible. L'icône est dessinée par script : tuile sombre de la famille, cube isométrique aux arêtes ambre `FFB454`, une arête cachée en pointillé cyan `5CE1E6`.
- **D11 — Vérifier sans écran.** `--snapshot sortie.png [fichier.skp]` photographie la fenêtre avec le modèle chargé (`SCNView.snapshot()` : `cacheDisplay` ne voit pas Metal) ; `--self-test [fichier.skp]` vérifie l'en-tête, le framework, une scène synthétique (cube), un vrai fichier si donné, et un PNG non uniforme.
- **D12 — Déplacement : quatre façons qui coexistent, aucune « à la SketchUp »** (Adrien : « je n'aime pas du tout le moyen de se déplacer dans SketchUp »). Une seule caméra (`CameraRig` : position, lacet, tangage, distance à la cible, horizon toujours droit), animée à 60 Hz seulement quand quelque chose bouge. Orbite fluide à la souris (glisser = orbite autour du point visé avec inertie, ⇧-glisser ou bouton du milieu = panoramique, molette = zoom vers le curseur, double-clic = recentrer) ; éditeur de jeu (clic droit tenu = regarder, ZQSD/WASD par touche physique et flèches, espace/E et C = monter/descendre, ⇧ = ×4) ; gestes trackpad (deux doigts = orbite ou zoom selon les Réglages, ⌥ = panoramique, pincer = zoom, rotation = lacet sans roulis) ; vol libre (⌥⌘F, Échap). Le point visé est un test de collision sur les faces seules (catégorie 1) : SceneKit teste les éléments `.line` comme des triangles. Écarté : le contrôleur d'orbite de SceneKit, le roulis.
- **D13 — Rendu « réaliste doux »** (Adrien : « metal, shading, on doit pouvoir faire bien mieux »). Matériaux physiques (rugosité 0,85, métal 0, couleurs et textures du fichier, double face, verre `.dualLayer`), soleil directionnel à 45° avec ombres douces en 3 cascades de 2 048², ciel dégradé procédural comme environnement lumineux, caméra HDR sans adaptation, occlusion ambiante écran, anticrénelage ×4 ; interrupteurs Ombres (⌥⌘O) et Occlusion ambiante (⌥⌘A). Quatre écarts au design, décidés sur les captures (d6 de `.project-map/decisions.md`) : soleil venant du sud-ouest (azimut compté depuis +X, sinon les ombres tombent hors de la vue iso) ; fond = bandeau de ciel en espace écran (l'équirectangulaire ne montrait que le sol gris vu de dessus) ; arêtes grises opaques (0,3), les arêtes à 60 % d'alpha disparaissaient ; occlusion ambiante coupée en projection parallèle (elle noircit des faces entières), réappliquée à chaque changement de projection. Revue du 25 octobre : exposition −0,8 (−0,5 brûlait le sol ensoleillé d'Arles) ; occlusion ambiante adoucie (rayon 0,3 m, biais 0,08, seuil de profondeur 2, intensité 0,7) et **coupée par défaut** : aucun réglage ne donnait l'ombre des coins sans bandes sur les sols ouverts (seuil 0,3) ou mouchetures des murs lointains (seuil 1). Ombres et occlusion ambiante sont mémorisées (Préférences). Avec ces réglages l'occlusion est quasi invisible même activée (écart moyen 0,05/255 sur Arles) : l'interrupteur reste pour une future mise au point.
- **D14 — Fusion des instances par ensemble de calques.** L'arbre des instances est aplati une fois ; toutes les faces d'un même ensemble de calques (calques du chemin) et d'un même matériau sont fusionnées en une géométrie en espace modèle, découpée en morceaux spatialement compacts de ≤ 250 000 triangles (ordre de Morton), et toutes ses arêtes en une géométrie `.line` : ≈ 185 appels de dessin au lieu de 50 000 nœuds. Un ensemble se construit la première fois que tous ses calques sont visibles. Les sommets, normales et UV fusionnés vivent dans des `MTLBuffer` en mémoire partagée donnés tels quels à SceneKit (une seule copie : des sources `Data` étaient gardées par SceneKit et recopiées pour le GPU) ; les indices des faces restent en `Data` (constaté : un élément fait d'un `MTLBuffer` ne renvoie aucune collision). Salle de 97 Mo : iso 17 → 118 i/s ombrée, construction 0,15 s, empreinte 1,2 Go en vue du fichier. Écarté : garder des instances (aucun composant de la salle ne dépasse 50 000 triangles répétés), un moteur Metal maison.
- **D15 — Pilotage OSC, OSCQuery (`OSCScore`), API HTTP `/v1` et MCP (`simpleskp-mcp`) + réglages fins de la caméra** (Adrien, 25 octobre 2026 : « pouvoir contrôler la caméra dans OSCScore » et « régler un peu plus finement la caméra : angle d'ouverture, etc. »).
  - Grille de ports `SimpleFamily` (G92, `x = 5`) : réception OSC UDP sur `:9150` (`SIMPLESKP_OSC_IN_PORT`), retour OSC UDP sur `127.0.0.1:9151` (`SIMPLESKP_OSC_OUT_PORT`), API HTTP `/v1` et arbre OSCQuery (`/` et `/?HOST_INFO`) sur `:17950` (`SIMPLESKP_API_PORT`), annoncés en Bonjour via `_oscjson._tcp.` et `_osc._udp.`.
  - Découverte automatique dans **OSCScore** : l'arbre OSCQuery expose `/simpleskp/camera/position` (`fff`, piste Vec3), `/simpleskp/camera/target` (`fff`, piste Vec3), `/simpleskp/camera/orientation` (`ff`, lacet/tangage en degrés), `/simpleskp/camera/fov` (`f`, `10°…120°`), `/simpleskp/camera/focal` (`f`, focale 24×36 en `mm`), `/simpleskp/camera/exposure` (`f`, `-3…+3 EV`), ainsi que les scènes, calques, styles de rendu, soleil, lumières ponctuelles et fond.
  - Binaire compagnon `simpleskp-mcp` livré dans `SimpleSKP.app/Contents/MacOS/simpleskp-mcp` exposant 8 outils MCP (`simpleskp_state`, `simpleskp_help`, `simpleskp_open`, `simpleskp_camera`, `simpleskp_scene`, `simpleskp_layers`, `simpleskp_rendering`, `simpleskp_snapshot`).
  - Popover **Caméra & Optique** dans la barre d'outils : ouverture verticale (`10°…120°`), focale équivalente 24×36 (`14`, `24`, `35`, `50`, `85 mm`), coordonnées exactes `X, Y, Z` (`m`), `Œil 1,70 m`, `Au centre`, `Horizon 0°`, azimut/inclinaison et exposition HDR.

## Constaté

- Essai du 25 octobre 2026 : le framework se charge en **116 ms** une fois ses dylibs sœurs préchargées par chemin absolu ; il lit le fichier de **97 Mo** (`B-SEINE MUSICALE-GRANDE SALLE TECHNIQ V40.skp`, 20 scènes, 151 calques) en **2,9 s**, celui de **45 Mo** (`MM_Arles_3D_V003.skp`) en **1,9 s**, un petit fichier en 0 ms.
- Avec le SDK embarqué (copie Unity, 25 octobre 2026) : un seul `dlopen` de `Versions/A/SketchUpAPI` en **48 ms** (son `LC_RPATH @loader_path/Libraries` trouve les dylibs, rien à précharger), le fichier de 97 Mo lu en **3,0 s** à l'essai (4,9 s dans le `--self-test` du bundle debug avec `SIMPLESKP_BUNDLED_SDK_ONLY=1`). App debug : **13 Mo**, dont 11 Mo de framework aminci à arm64 sans en-têtes (22 Mo universel avec en-têtes).
- Les en-têtes officiels du SDK se lisent dans la copie Unity (`SketchUpAPI.framework/Versions/A/Headers`) ; les prototypes en sont transcrits.
